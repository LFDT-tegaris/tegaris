## Maintainer scope

All active maintainers share the **Maintainer** scope: source and documentation review, contribution triage, compatibility decisions and release preparation. All maintainers also serve on the [security response team](SECURITY.md#security-response-team).

This file records project responsibilities. Repository permissions and GitHub team membership are provisioned separately by authorized administrators. A listed scope does not grant access or establish a production support arrangement.

## Contact and review

Use repository issues for product questions and contribution discussions. For vulnerabilities, use the private reporting routes in [SECURITY.md](SECURITY.md).

For an ordinary contribution, explain the affected component and user behavior in the issue or pull request. A maintainer can help identify the appropriate reviewer. For an interface or security-sensitive change, seek a reviewer familiar with that boundary rather than treating any approval as equivalent technical coverage.

## Maintainer responsibilities

- Keep owned contracts, code, tests and documentation consistent.
- Review allowed, rejected and recovery behavior relevant to a change.
- Triage reproducible defects and help resolve regressions.
- Record compatibility and release-scope decisions clearly.
- Maintain current contact and review-ownership information.
- Coordinate confidential issues through the security process.

## Maintainer changes

Nominations and changes follow [GOVERNANCE.md](GOVERNANCE.md). Submit changes to these lists through a pull request. After a change is accepted, coordinate the corresponding GitHub team and repository-access updates with authorized LFDT administrators. Update the security response roster at the same time.
