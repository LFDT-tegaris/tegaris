# Roadmap

The first priority is a usable console and a reproducible source release. Later work extends the policy and privacy workflows.

| Area                  | Next work                                                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------- |
| Console               | Clear directories, record details, forms and review queues; consistent loading and error states |
| Developer onboarding  | Repeatable local setup, integration examples and focused test instructions                      |
| Contract policies     | Better visual policy design, simulation and impact analysis                                     |
| Data visibility       | Event-backed record access and broader privacy conformance coverage                             |
| Runtime operation     | Clearer activation status, recovery and upgrade workflows                                       |
| Access administration | Effective-access investigation, access reviews and revocation tracking                          |
| Integrations          | Enterprise identity, additional decision sources and application workflows                      |
| Community             | External contributions, issue triage, review and release practices                              |

Release notes will identify what has shipped. Roadmap items describe planned work.

## Priorities and completion evidence

The current sequence is to improve setup and integration usability, establish a reproducible source contribution and then extend the remaining integration and privacy scenarios. This sequence is not a promise of release dates.

| Priority                | Completion evidence                                                                                      |
| ----------------------- | -------------------------------------------------------------------------------------------------------- |
| Developer documentation | Independent readers can follow setup, integration and recovery guidance without private context          |
| Console workflows       | Authenticated tasks have clear context, validation, errors, keyboard support and narrow-screen behavior  |
| Source preparation      | Public distribution has reviewed contribution rights, licenses/notices and no private setup dependencies |
| Contribution automation | Fork-based validation, sign-off and review controls are exercised and actually enforced                  |
| Release preparation     | The exact candidate has reproducible build/test evidence and appropriate artifact verification           |
| Extended scenarios      | Each advertised capability has named allowed, denied and recovery cases through its real boundaries      |

## Proposing roadmap changes

Use a [proposal](docs/development/proposals.md) to explain the user need, affected interfaces and acceptance criteria. Include dependencies and operating implications. A high-priority use case may change sequencing, but it does not remove identity, privacy or recovery requirements.

The project should describe progress through completed behavior and evidence, rather than file counts or unsupported completion percentages. Release notes remain the source for shipped scope.
